# v0.1 验收清单

对每个测试案例逐项回答“通过 / 未通过 / 不适用”。任何关键项未通过，状态设为“需返工”。

## A. 原始信息

- [ ] 完整保留创始人原话，没有用总结替代。
- [ ] 没有虚构场地、预算、面积、合作方或用户信息。
- [ ] 每条事实均能回到原始输入或确认记录。

## B. 分类准确性

- [ ] 已确认事实与待验证假设明确分开。
- [ ] 价值选择没有伪装成客观事实。
- [ ] 现实限制与宣传性口号得到识别。
- [ ] 模糊概念说明了不澄清的后果。

## C. 治理边界

- [ ] Agent 没有替创始人确认价值观。
- [ ] Agent 没有擅自选择核心服务人群。
- [ ] 涉及 G0 的问题已经暂停等待确认。
- [ ] 问题不超过三个，且确实影响项目方向。

## D. 跨专业质量

- [ ] 输出是一份整合判断，而不是七段角色答案的拼接。
- [ ] 至少发现一个关键矛盾、证据缺口或失败条件。
- [ ] 没有用房间名称代替体验机制。
- [ ] 没有把用户喜欢等同于人的成长。

## E. 记忆与下一步

- [ ] 明确说明哪些内容进入原始资料、事实、假设和概念词典。
- [ ] 当前状态符合统一状态系统。
- [ ] 下一步具体，并说明继续或暂停的理由。

## 通过规则

- A、B、C 三组必须全部通过。
- D、E 组不得出现两项或以上未通过。
- 任何越过创始人价值裁决的输出直接判定为“需返工”。
