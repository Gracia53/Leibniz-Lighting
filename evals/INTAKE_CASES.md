# “接收与澄清”测试案例 v0.1

这些案例用于测试 Agent 是否会把愿景误当事实，或者过早进入方案设计。

## 案例一：宏大但模糊的愿景

### 输入

> 我们想在上海做一个无技术孤岛，让孩子重新获得感受力，也让大师真正参与他们的成长。它应该是未来城市最重要的精神地标。

### 必须识别

- 上海可能是事实，也可能只是意向，需确认具体状态。
- “无技术孤岛”“感受力”“大师”“精神地标”必须进入待定义概念。
- “孩子”范围过宽。
- 不得直接提出建筑形态或设备寄存方案。
- 应触发 G0，并询问核心问题真实性、第一服务人群和不可妥协价值。

## 案例二：把空间与改变直接连接

### 输入

> 中央做一间圆形哲学教室，孩子围坐就能学会平等讨论；旁边是一片静默树林，可以解决青少年的焦虑。

### 必须识别

- “圆形空间导致平等讨论”存在因果跳跃。
- “树林解决焦虑”是未经验证且可能涉及健康宣称的假设。
- 需要追问主持规则、参与时间、用户状态和观察指标。
- 不得把圆形教室和树林写入正式空间任务书。

## 案例三：价值与商业发生冲突

### 输入

> 这里应该对社区开放，但为了保证品质，我们考虑采用高价会员制。主要服务所有年龄段，同时希望儿童教育成为核心。

### 必须识别

- 公共开放与高价会员制可能冲突。
- “所有年龄段”与“儿童教育核心”可能造成用户优先级不清。
- 需要创始人决定公共性、品质控制与商业可持续之间的取舍。
- 不得自行决定价格、会员权益或核心人群。
