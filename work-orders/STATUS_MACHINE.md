# 工单状态机 v0.3-pilot

工单必须且只能有一个当前状态。

## 状态定义

| 状态 | 含义 | 允许发生的工作 |
|---|---|---|
| 待澄清 | 问题、范围或验收标准尚不清楚 | 保存原话、分类、提出最多三个关键问题 |
| 研究中 | 在已批准范围内收集和核查知识 | 研究、证据核查、案例比较 |
| 待决策 | 存在必须由创始人选择的方向 | 整理选项、依据、代价；不得替创始人选择 |
| 已确认 | 当前范围与所需决定已有有效出处 | 编写执行计划，准备进入研究或设计 |
| 设计中 | 正在形成体验、空间、文化或运营方案 | 推导、建模、原型设计 |
| 验证中 | 正在对照验收标准、实验或审查 | 测试、红队、独立审查、逐条验收 |
| 需返工 | 至少一项关键验收未通过 | 修正问题，不扩大范围 |
| 已交付 | 当前任务的交付物和复盘已完成 | 呈交、等待后续采用决定 |
| 暂缓 | 因优先级、资源或外部条件暂时停止 | 保留现场，记录重启条件 |

## 允许的主要转换

```text
待澄清 → 待决策
待澄清 → 已确认
待决策 → 已确认
待决策 → 暂缓
已确认 → 研究中
已确认 → 设计中
研究中 → 待决策
研究中 → 设计中
研究中 → 验证中
设计中 → 待决策
设计中 → 验证中
验证中 → 需返工
验证中 → 已交付
需返工 → 研究中
需返工 → 设计中
需返工 → 验证中
任一未交付状态 → 暂缓
暂缓 → 待澄清 / 待决策 / 已确认 / 研究中 / 设计中
```

## 禁止的转换

- `待澄清 → 已交付`：没有范围与验收。
- `待决策 → 设计中`：跳过创始人决定。
- `研究中 → 已交付`：跳过验证。
- `设计中 → 已交付`：跳过验证。
- `需返工 → 已交付`：没有重新验证。
- 任意状态自动改变G0—G4：工单状态不能代替创始人闸门。

## 每次状态变化必须记录

```yaml
from: 待澄清
to: 待决策
changed_at: YYYY-MM-DD
changed_by: 莱布尼茨 / 创始人 / 审查者
basis: "文件、决策编号或验收结果"
reason: "为什么改变"
next_entry_condition: "进入下一状态还需要什么"
```

如果缺少 `basis`，状态变化无效。
