# 03｜任务与验收标准

## 当前问题

怎样以足够轻量的制度，把模糊请求变成可追踪、可暂停、可验收、可返工和可复盘的工作？

## 背景

立宪层已经确认，但项目目前只有澄清Prompt和记忆模板，没有统一任务编号、类型、状态转换和交付账本。

## 工作范围

- 定义轻量任务、正式任务和立宪任务的适用边界；
- 定义与宪法一致的九种状态及转换；
- 建立正式任务的一张主工单和六件过程账本；
- 建立轻量任务模板；
- 建立公开工单索引；
- 使用本次工作建立首张真实示范工单；
- 更新莱布尼茨指令、项目说明和实施路线。

## 明确不做

- 不实现自动调度、提醒或数据库；
- 不建立新的独立Agent；
- 不提前实现第三至第五阶段；
- 不改变G0状态；
- 不把自检称为独立审查。

## 验收标准

- [ ] 任务分类有可判断的升级条件。
- [ ] 状态名称与宪法完全一致。
- [ ] 禁止跳过创始人决定和验证阶段。
- [ ] 六件账本分别承担不同责任，没有用摘要替代原文。
- [ ] 正式任务没有验收标准时不能执行。
- [ ] 模板区分交付与创始人采用。
- [ ] 模板包含公开/私密级别。
- [ ] 模板明确自检不等于独立审查。
- [ ] 首张工单使用自身制度并可追溯。
- [ ] 所有本地链接和YAML格式有效。

## 证据要求

- 以已确认宪法和决策记录作为治理依据。
- 以模板、状态转换和首张真实工单作为机制可用性的证据。

## 现实限制

- 时间：当前阶段完成制度草案和一次自用验证。
- 资源：一个莱布尼茨，无独立Agent。
- 隐私：只处理公开的制度内容。
- 技术：使用GitHub文件，不接数据库。

## 风险与停止条件

- 工单结构明显重复或难以填写时停止扩张字段。
- 需要改变创始人权力边界时停止并走修宪程序。
- 发现私密资料时停止公开写入。

## 工作计划

1. 写工单制度与状态机。
2. 写轻量和正式模板。
3. 用本次任务建立首张工单。
4. 更新现有项目入口和Agent指令。
5. 执行格式、一致性和红队检查。
6. 呈交创始人确认是否进入试运行。
