# 01｜澄清与分类

## 问题层级

- 主要通道：设计任务单
- 项目步骤：治理建设第二阶段
- 工单类型：formal
- 当前状态：已确认

## 信息分类

### 已确认事实

- 创始人已确认采用工单机制，见 `DEC-20260825-002`。
- 创始人已确认五项立宪结构，见 `DEC-20260825-003`。
- 创始人明确要求继续工单层，见原始请求。
- 当前保持一个莱布尼茨与七种思考视角。

### 待验证假设

| 假设 | 为什么未确认 | 验证方式 |
|---|---|---|
| 六件过程账本足以覆盖早期正式任务 | 尚未在多个真实任务中使用 | 用三类任务连续试运行并记录缺口 |
| 轻量/正式两类分流不会造成误判 | 尚无实际升级案例 | 检查首批十张任务的分类与返工 |
| 九种中文状态足够表达工单进度 | 尚未经历长期阻塞和多轮返工 | 记录无法表达的状态，不提前新增 |

### 价值选择

- 可靠、可追溯和可验收优先于快速给出方案。
- 工单制度不能削弱创始人价值裁决权。

### 现实限制

- 当前没有自动调度、数据库和独立Agent。
- 第四阶段独立审查制度尚未实施。
- 公开仓库不能保存私密项目材料。

### 待定义概念

| 概念 | 当前可能含义 | 不澄清的后果 |
|---|---|---|
| 已交付 | 当前工单成果已经呈交，不等于创始人正式采用 | 可能把提交误记为批准 |
| 已确认 | 当前工作范围或所需决定已有出处 | 可能误认为G0—G4已通过 |
| 独立审查 | 非主导作者依据验收标准检查 | 可能把自检包装成独立意见 |

## 七种视角相关性

| 视角 | 必须参与 / 轻量检查 / 不适用 | 原因 |
|---|---|---|
| 人类愿景 | 轻量检查 | 检查工单是否保留人的改变目标 |
| 城市建筑 | 轻量检查 | 保证未来空间任务可以写出行为与场地条件 |
| 生活方式 | 轻量检查 | 保证任务可容纳日、季和长期体验要求 |
| 教育艺术 | 轻量检查 | 保证课程、作品和驻留任务可使用同一结构 |
| 文化品牌 | 轻量检查 | 保证公开成果与传播任务有明确验收 |
| 运营商业 | 必须参与 | 状态、责任、资源与交付属于运营核心 |
| 红队伦理 | 必须参与 | 防止官僚化、假批准和隐私泄漏 |

## 关键矛盾与失败条件

- 工单太轻会失去可追溯性；太重会让简单任务无法推进。
- “已确认”可能被误解为创始人通过价值闸门。
- 在独立审查制度尚未建立时，不能制造已经独立审查的假象。

## 最多三个创始人问题

本工单不需要新的价值裁决。制度草案完成后，只需创始人确认工单结构是否可以进入试运行。
